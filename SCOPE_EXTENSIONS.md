# Explicit session scope and interpretation

These decisions come from the user's session rather than invented source-document approval.

| Session requirement | Treatment in this pack | Remaining evidence |
| --- | --- | --- |
| First improve one service, then expand | HVAC is the current concrete domain pack; propose it for the first reviewed service slice | Client confirms contracted pilot brands/packs/launch wave |
| Let AI create original service-specific layouts/CSS | Current Gemini website authoring uses original HTML/CSS, with safety/platform interactions and visual review | Record renderer exception/ADR against the source SiteSpec baseline; premium quality still requires acceptance |
| Continue with Gemini for now | Preserve the current choice while implementing provider contracts/evaluation | No unsupported claim that free-tier capacity or a model is best/production-sufficient |
| Each service needs different skills and website standards | Retain shared guardrails plus distinct reviewed service packs and design briefs | Only HVAC/general exists; additional packs and full memory policy remain planned |
| Customers connect their own project repositories | EVN-PJM-101 delivers tenant-scoped GitHub docs access | Hosted current app rollout and genuine authorised private-repository journey |
| Project > modules > tickets, with business and technical deliverables | EVN-PJM-102 delivers this client checklist pack | Client reviews scope/owners/acceptance and team maintains statuses |
| Translate means business-to-technical mapping only | Every ticket maps the client outcome to records/services/UI/evidence | Actual source language requirements stay in their relevant channel/vertical tickets |
| Publish Markdown to GitHub, then connect the repo to Project Management | This repository contains only `.md` documentation | Complete Git publication and client connects branch `main`; no TSV/JSON/CSV files are deliverables |

The Project Workspace is a read-only Markdown repository viewer, with manual sync and filename/path search. Markdown tickets/tasks can be browsed, but the integration does not create GitHub Issues, execute repository skills, write customer repositories or automatically materialise tickets into a database. Those capabilities would be separate agreed enhancements.

Business facts/design change requests should be approved tenant inputs. Platform safety, authorisation, secret handling and provider/tool policy remain controlled application configuration. Viewing an arbitrary customer's Markdown cannot override them.
